# Скиллы по ролям: матрица доступа

Дата: 2026-11-17. Кит 0.12.0. Источник правды — фронтматтер `profile/agents/*.md`, поле `permissions`; этот файл — объяснение, а не настройка. Правку вноси в агента и здесь одной задачей.

## Механика

Побеждает **последнее совпавшее** правило, поэтому общий `allow` идёт первым, исключения — после. Шаблоны цельные: `*` и `?`; `*` ест и `/`, и `\`. Для `read`/`edit` ресурс — путь от корня проекта, для `shell` — строка команды.

Отказ — штатный ответ, а не сбой: роль пишет об этом в отчёт и не обходит правило.

## Модель

Разрешено всё, запрещено только то, что нельзя делегировать модели:

| Действие | Правило |
| --- | --- |
| `skill` | разрешены все: скилл — знание, а не действие |
| `edit` | `src/*` — только Колдуну, `.git/**` — никому, остальное открыто |
| `shell` | `ask` по умолчанию; без вопроса — `scripts/run.ps1`, `node …/skill-web-test/run.mjs`, сборщик PDF у Барда, `python scripts/sync/sync.py` у Телепата |
| `subagent` | у субагентов закрыт всегда; Коммандер зовёт шесть ролей плюс `researcher` и `general` |
| `question` | Коммандеру |

## Что это значит по ролям

- **Коммандер** правит `AGENTS.md`, `docs/` и папки задач — память проекта его работа; код закрыт.
- **Оракул, Инквизитор, Бард, Телепат** пишут любые файлы, кроме кода конфигурации.
- **Колдун** — единственный, кто правит `src/`.
- Скиллы не раздаются списками: роль сама решает, что загрузить под задачу.

## Изменение 2026-11-17

Сняли списки разрешённых скиллов по ролям и узкие шаблоны `shell`: на слабых моделях они давали больше отказов, чем пользы. Остались три границы — `src/`, `.git/`, вложенные субагенты. Вернуть строгость можно точечно: `deny` на скилл или команду в промпте нужной роли.

## Как менять

1. Правка — во фронтматтере агента: общий `allow`, затем исключения; порядок правил важен.
2. Сверить id скиллов с каталогами: `profile/skills/*`, `profile/rules/on-demand/*`, `~/.config/opencode/skills/*`.
3. Обновить таблицу здесь, затем `install\kit.ps1 lock`, `verify`, `apply`.
