# Маршруты и роли

## Сервис задач

Задачи ведутся в **PiPa** (PithosPandoras) — локальный сервис задач с MCP `pipa`.
Имя проекта берётся из раздела «Сервис задач» в `AGENTS.md` проекта. Раздела нет —
не угадывай проект и не создавай задачу: спроси человека.

Сервис держит состояние: задача, этапы, отчёты, статусы, файлы. Он проверяет
только механику — одна роль в этапе, один открытый этап на задачу, один отчёт
одного вида, отчёт после публикации не редактируется, задачу нельзя закрыть с
открытым этапом. Порядок ролей и качество работы проверяют правила и Коммандер.

## Как выбрать маршрут

Маршрут выбирается один раз, при `task_create`, по типу работы. По умолчанию —
`быстрый`. Одно поле или текст без новых метаданных — `правка`; метаданные,
форма, СКД, роль, расширение, интеграция — `полный`; нужен гайд человеку —
`релиз`.

| Маршрут | Роли | Когда |
|---------|------|-------|
| `справка` | Оракул | «где в коде», «что за версия» — отчёт `research`, без этапов |
| `правка` | Колдун | текст интерфейса, заголовок, представление, один метод без проверки поведения |
| `быстрый` | Колдун → Инквизитор | один метод или форма; ≲20 строк BSL; без транзакций, публичного API, adopted CFE, RLS |
| `полный` | Оракул → Колдун → Инквизитор | новая метаданка, форма, СКД, роль, расширение, интеграция |
| `релиз` | полный + Бард | то же, но нужен гайд для человека |
| `синхронизация` | Телепат | перенос объектов между базами |

Маршрут — метка задачи и правило для агентов; сервис его не исполняет.
Начинай работу с `/Задача`: команда заводит задачу и первый этап.

## Цикл

```text
Коммандер: task_create(statement с критерием готовности) → номер и folder_path
  роль: task_get → stage_start (повтор той же ролью вернёт resumed) → работа
        → report_open → report_section → report_publish → stage_finish(report_id)
  Коммандер: task_next → stage_start следующей роли
  все этапы закрыты → task_close(role="Коммандер")
```

Возврат — новый круг, а не правка старого отчёта:

```text
Инквизитор: stage_finish(verdict="на доработку", kind="acceptance", report_id="…")
  Колдун: новый круг; входы — свой прошлый отчёт и возврат
  Инквизитор: новый круг
```

## Закрытие этапа

Этап не оставляй открытым. Как только работа по существу сделана, публикуй отчёт
и вызывай `stage_finish` по `report_id` — до последних необязательных проверок,
скриншотов и правки формулировок. Незаконченная проверка — это новый круг, а не
повод держать этап открытым. Текста `report` в `stage_finish` больше нет: отчёт
пишется в черновике (`report_open` → `report_section` / `report_append` →
`report_publish`).

Если видишь, что работы много, дели её на круги сам: сначала закрытый этап с тем,
что проверено, потом следующий. Роль, которая остановилась без `stage_finish`,
оставляет задачу висящей: Коммандер видит открытый этап и пустой результат. Ход
длинной работы отмечай `stage_note` — он обновляет `last_activity_at`.

## Роли

| Роль | Когда работает | Отчёт | Чего не делает |
|------|----------------|-------|----------------|
| **Коммандер** | ведёт задачу: ставит постановку, открывает этапы, закрывает | — | не пишет код, не читает отчёты целиком, не зовёт ролей вне этапов |
| **Оракул** | `справка`, `полный`, `релиз` — разбор и план | `plan` | не правит код и данные, не выбирает реализацию за Колдуна |
| **Колдун** | все маршруты правки — код, метаданные, загрузка в базу | `report` | не проверяет своё поведение на живой базе |
| **Инквизитор** | `быстрый`, `полный`, `релиз` — поведение на живой базе, дефекты `D1…Dn` | `acceptance` | не правит исходники и не гоняет статику заново |
| **Бард** | `релиз` — гайд для человека | `guide` | не меняет смысл, не пишет код |
| **Телепат** | `синхронизация` — перенос объектов | `report` | не подключается к рабочей базе |

## Вердикты

Два слова на все роли:

- `готово` — работа сделана, у Инквизитора — приёмка пройдена;
- `на доработку` — есть дефекты, работа возвращается Колдуну.

Слово пишется буквально: сервис распознаёт возврат только по `на доработку`
(и по `return`, `returned`, `возврат`). «На доработку» и «доработка» — не возврат.

Остановка — не вердикт: `stage_note` с состоянием, затем
`task_block(reason, waiting_for)` — он закрывает открытый этап. Продолжение —
`task_resume`, потом новый `stage_start` (старый этап не продолжается). Ждёшь
внешнего события дольше 10 минут — так и напиши в заметке, а этап закрой с тем,
что уже проверено.

## Делегирование

- Роль зовут по `task_next`/`stage_start`, а не «на всякий случай».
- Роли идут по одной: один открытый этап на задачу, параллельных этапов нет.
  Повторный `stage_start` той же ролью безопасен (вернёт тот же этап,
  `resumed: true`); этап чужой роли — `conflict` с именем владельца.
- Роли не запускают других ролей — вложенность закрыта правами.
- Неизвестная роль или проект — остановка и просьба зарегистрировать, а не
  выдуманное имя.
- Отчёт не переписывается. Ошибка исправляется новым отчётом или новым кругом.

## Параллельная работа

Несколько независимых работ — несколько задач. Сбор материалов по одной задаче
идёт без этапов: каждый агент пишет `report_add(kind="research")`, оркестратор
читает отчёты и закрывает задачу. Общий ресурс (база, стенд) помечается
одинаковым `resource` при создании задач.

## Передача сессии

Handoff пишет ведущий агент: файл в папку задачи, если она есть, иначе в
`handoffs/`. Подробности — скилл `skill-handoff`.
