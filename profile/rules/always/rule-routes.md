# Маршруты и роли

Единственный источник таблицы маршрутов и каталога ролей. Детали цикла — `rule-subagent-pipeline`, правила ведения задачи — промпт `Коммандер`.

Каркас задачи один на машину и глобальный: `%USERPROFILE%\.config\opencode\scripts\taskctl.ps1`, команды `/Задача`, `/Продолжить`, `/Статус` — `%USERPROFILE%\.config\opencode\commands`. Состояние задачи живёт в проекте, в `Задачи\`; скрипт находит корень вверх по каталогам.

## Как выбрать маршрут

Маршрут выбирается один раз, при `new --route`, по типу работы. Сомневаешься между `быстрый` и `полный` — бери `полный`: лишний круг дешевле разбора «почему проверка не заметила».

| Маршрут | Роли | Когда |
|---------|------|-------|
| `полный` | Оракул → Часовщик → Колдун → Инквизитор → Бард | новая метаданка, форма, СКД, роль, расширение, интеграция |
| `быстрый` | Колдун → Инквизитор | один метод / форма; ≲20 строк BSL; без транзакций, публичного API, adopted CFE, RLS |
| `синхронизация` | Телепат | перенос объектов между базами |

Начинай правку с маршрута каркаса: `/Задача` (глобальная команда) ведёт её через `taskctl.ps1` по `rule-routes`. Короткая правка без ролей — только когда маршрут явно не нужен; состояние задачи в чате не держим.

## Каталог ролей

| Роль | Когда работает | Чего не делает |
|------|----------------|----------------|
| **Коммандер** | ведёт задачу любой маршрут: `next` → `start` → роль → `finish` | не пишет код, не читает артефакты целиком, не зовёт ролей вне `next`/`start` |
| **Оракул** | `полный` — разбор постановки на живых данных; базовый замер «до» — его шаг | не читает код, не выбирает реализацию |
| **Часовщик** | `полный` — разведка, план, приёмка | не пишет код, не проверяет свою приёмку |
| **Колдун** | все маршруты правки — код, метаданные и статика | не правит приёмку, не закрывает свои дефекты, не доказывает поведение на живых данных |
| **Инквизитор** | все маршруты правки — поведение на живой базе | не правит исходники, не гоняет линтеры заново |
| **Бард** | `полный` — инструкция для пользователя | не меняет смысл, не пишет код |
| **Телепат** | `синхронизация` — перенос объектов | не подключается к рабочей базе |

## Делегирование

- Роль зовут по `next`/`start`, а не «на всякий случай»: порядок и переходы считает `taskctl`, а не модель.
- Роли идут по одной. Параллельная работа запрещена: второй процесс на задачу получает код 4.
- Роли не запускают других ролей — вложенность закрыта правами.
- Состояние и журнал пишет только скрипт. Один файл — один писатель.
- Роль возвращает короткий конверт по навыку `Формат-ответа` (роль загружает его сама) с вердиктом; подробности — в артефакте.
- Перечень допустимых вердиктов держит только скрипт: `finish` называет их в отказе (`можно: …`). Другого перечня нет.
- Нет артефакта — нет перехода: `finish` не примет этап. Возврат требует раздела «Причина возврата» со ссылкой на артефакт спора.
