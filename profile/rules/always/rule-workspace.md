# Правила проекта

Действуют всегда и в любой роли. Маршрут задачу ведёт `Коммандер` — правила ведения в его промпте.

**SoT:** маршруты, переходы и вердикты — глобальный `%USERPROFILE%\.config\opencode\scripts\taskctl.ps1` (исходник кита — `profile/scripts/taskctl.ps1`); роль — её промпт в `%USERPROFILE%\.config\opencode\agents` (исходник — `profile/agents/`); гейты проверок — on-demand правило `rule-verification-checklist` (его грузит тот, кто закрывает гейт). Правь SoT кита (`profile/rules/`, `profile/agents/`, `profile/scripts/`, `profile/commands/`) и запускай `kit.ps1 apply` — этот слой перезаписывается при apply.

## Где что лежит

Рабочие материалы задачи — артефакты, проверки, сценарии, скриншоты, заметки — живут в папке задачи. Вне задачи только исходники `src/`, сборка `build/` и проектная справка `docs/`; передача сессий — в папку задачи, если задача есть, иначе `handoffs/`. В корень проекта ничего не складывать. Имена папок и файлов — как читается, в том числе по-русски.

## Запрещено

Внешние MCP и реестры для операций с конфигурацией и ИБ; сторонние установщики и команды развёртывания; ручные вызовы Конфигуратора/`1cv8` в обход скиллов контура; ручная правка XML.

Поиск по исходникам 1С — правило `rule-mcp-first-search` (индекс → grep с обоснованием; детали — скилл `skill-bsl-analyzer`). Читает тот, кто ищет.

## Память проекта

- Корневой `AGENTS.md` проекта — единственная always-on память: короткие правила и невыводимые факты, которые нужны в каждой сессии. OpenCode загружает его автоматически.
- Приёмка записи: **невыводимо** из кода/конфигов/docs + **стабильно** + **меняет поведение** + **не дублирует** глобальные правила, скиллы и `docs/`. Иначе — не писать.
- Детали и runbook — `docs/<тема>.md`, в `AGENTS.md` только ссылка. Правила подсистемы — вложенный `AGENTS.md` рядом с кодом: он подхватывается, когда агент читает файлы этой области.
- Состояние работы — папка задачи или `handoffs/`; история решений — `docs/decisions.md`, только если она реально нужна.
- Держать корневой `AGENTS.md` ≤ ~100 строк. При росте — выносить детали в `docs/`, оставляя ссылку.
- Не писать: обзор архитектуры, дерево файлов, очевидные правила стиля, секреты, логи, статусы задач и длинные операции.
- Запись — когда факт проходит критерии: по явной команде «запомни» или в конце задачи, если без него следующая сессия ошибётся. Сомневаешься — предложи пользователю; массово не дописывать. Хост-память агента — только личные коррекции, не дублировать.
- Handoff сессии — шаг ведущего агента: скилл `skill-handoff`, файл в папку задачи, если она есть, иначе в `handoffs/`. Роли-исполнители передачу не пишут.
