# Процесс разработки 1С в XML-выгрузке

Применяется при работе с исходниками конфигурации (`src/cf`), расширений (`src/cfe`), внешних обработок/отчётов (`src/epf`, `src/erf`). Что должно быть зелёным до «готово» — в `rule-verification-checklist`.

## Как менять

- **Не редактируй XML-файлы 1С напрямую руками.** Структура конфигурации, расширения, форм, макетов, СКД, ролей, подсистем, командного интерфейса меняется только профильными скиллами: `meta-*`, `form-*`, `skd-*`, `mxl-*`, `role-*`, `subsystem-*`, `interface-*`, `cfe-*`, `epf-*`, `erf-*`, `xdto-*`.
- Не создавай вручную каталоги и файлы `Forms`, `Commands`, `Templates`, `Ext/Template.*`, `Ext/Form.xml`, `Ext/Rights.xml`, `CommandInterface.xml` и записи `ChildObjects`, если для операции есть скилл.
- Для CFE с хранилищем (`repository` в `.v8-project.json`) — полный цикл `skill-repo-workflow`: захват до правки, шаги и гейты цикла не пропускаются. Пользователь не обязан каждый раз просить их отдельно.

## Версия

При каждой смене состава функционала расширения или внешней обработки/отчёта — `skill-versioning`, схема `X.Y.Z.W`: релиз / новый самостоятельный функционал, которого в объекте не было / развитие уже существующего сценария / мелкая доработка. Начальная версия пустого объекта — `0.1.0.0`. Новый сценарий в «большом» расширении — второе число, а не третье.

## Загрузка в ИБ

Только скиллы контура. Конфигуратор и `1cv8` вручную запрещены; внешние MCP и реестры для операций с ИБ — тоже. Скиллы контура недоступны → стоп, сообщить.

- Перед загрузкой — короткий summary пользователю: что менялось и что будет загружено.
- Основная конфигурация (`src/cf`): `db-load-xml` — полная или частичная по списку файлов (`-Files`/`-ListFile`); инкремент по изменениям — `db-load-git`, если проект в git.
- Расширение с хранилищем: `db-load-xml -Mode Partial` + `db-update -Extension`, затем commit через `db-repo`.
- Расширение без хранилища: `db-load-xml -Extension` + `db-update -Extension`.
- Внешние обработки и отчёты: `epf-build` → `build/out/epf`, `erf-build` → `build/out/erf`, не в корень `build/`.

## Порядок

1. Найди объект: `meta-info` / `form-info` / `skd-info`; ИБ и платформа — из `.v8-project.json` (`skill-project-context`).
2. Расширение с хранилищем — сначала захват по `skill-repo-workflow`.
3. Меняй профильным `*-edit` / `*-compile` / `cfe-borrow` / `cfe-patch-method` / `epf-bsp-*`; версию — по `skill-versioning`. Собственный объект расширения — с префиксом и `ObjectBelonging>Native`.
4. Валидация и остальные гейты — `rule-verification-checklist`, затем загрузка.

## Если инструменты недоступны

Остановись и сообщи, что недоступно. Не обходи это прямой правкой XML.
