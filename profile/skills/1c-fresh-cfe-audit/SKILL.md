# Аудит расширения (CFE) для 1С:Фреш

Вызывается из `1c-fresh-adaptation` или напрямую. Детальный чеклист: [checklist.md](checklist.md). Ручные шаги: [../1c-fresh-adaptation/manual-steps.md](../1c-fresh-adaptation/manual-steps.md) (разделы «Общие» + «Только расширения»).

## Алгоритм

1. Найди исходники расширения: каталог `src/cfe/<Имя>` или `Configuration.xml` расширения. При необходимости уточни список расширений в ИБ: MCP `1c-ninja-mcp` `live_extensions_list` (**главный способ**; не vrunner `extensions_list` / Предприятие), каталоги `src/cfe`, или ключи `repository.json` → `cfe`.
2. Прочитай свойства корня расширения (`meta-info` / `cf-info`, `Configuration.xml`):
   - уникальное **имя**;
   - задана **версия** (частая причина отказа аудита);
   - режим совместимости согласован с основной конфигурацией (если применимо).
3. `cfe-validate` (+ `meta-validate` по новым/изменённым объектам).
4. `cfe-diff` — состав заимствований и перехватчиков.
5. Если расширение **добавляет объекты данных** (справочники, документы, регистры, реквизиты и т.п.):
   - заимствовать план обмена `МиграцияПриложений`;
   - включить новые объекты в состав;
   - авторегистрация **запрещена**;
   - включить признак «Изменять значение при подключении расширения».
6. Поиск опасного кода (см. оркестратор) в модулях расширения по исходникам `src/cfe`.
7. Проверить длительные операции (≥10 с) → БСП; веб-клиент / ограничение «только тонкий».
8. Исходящие HTTP/интернет → список адресов для ручного указания разрешений при загрузке.
9. Сформировать отчёт оркестратора + блок **НУЖНА РУЧНАЯ НАСТРОЙКА**.

## Жёсткие требования (Blocker, если нарушено)

- Расширение должно быть работоспособно в безопасном режиме (и с профилем, если нужны исключения).
- Нет паролей на модули и обфускации.
- Не задана версия расширения → Blocker.
- Новые объекты данных без корректного `МиграцияПриложений` → Blocker.
- COM / чужие ВК / файловая система вне temp / приложения ОС / серверная криптография → Blocker.
- Универсальные опасные инструменты порчи данных → Blocker для аудита.

## Рекомендации разработки

- Разрабатывать на версии платформы и конфигурации как в сервисе.
- Вызывать программный интерфейс БСП/конфигурации, не копировать типовой код без нужды.
- Имена расширения — уникальные, с префиксом проекта.
- Формы — в стиле целевой конфигурации; ключевой функционал в веб-клиенте без расширения работы с файлами.
- Атомарные изменения — транзакции; параллельное редактирование — объектные блокировки; запросы — оптимальные (модель сервиса, многопользовательская нагрузка).
