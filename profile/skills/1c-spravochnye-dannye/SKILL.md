# Справочные данные в расширении 1С

Справочные данные — не отдельный механизм платформы, а связка двух слоёв:

1. **Метаданные** — `Catalogs/<Имя>/Ext/Predefined.xml`: имя, код, наименование, иерархия. Едут в Git и в CFE.
2. **ИБ** — все собственные реквизиты и ТЧ. В конфигураторе их заполнить нельзя.

Платформа при `PredefinedDataUpdate = Auto` создаёт недостающие предопределённые элементы при применении расширения. Длинный текст в XML не попадает.

## Выбор схемы

| Задача | Схема | Источник правды |
|--------|--------|-----------------|
| Описания доработок | Свой справочник + макет заполнения | Git (Predefined.xml + макет) |
| Настройки конкретной ИБ | Ключи предопределённые, значения в реквизитах | ИБ (как `НастройкиАвтоматизации`) |
| Классификатор для кода | Только предопределённые | Git (Predefined.xml) |
| Помощь по форме | `help-add` | `Ext/Help/ru.html` |

Не класть документацию доработок в справочник настроек и не заимствовать типовые предопределённые ради текстов.

В ecoladev уже есть паттерн **настроек** (не описаний):

- `src/cfe/РеквизитыИНастройки/Catalogs/ЭколаРеквизитыИНастройки_НастройкиАвтоматизации`
- `src/cfe/ОбменДаннымиСВИУ/Catalogs/ЭКЛО_НастройкиОбменаЭколы`

Код обращается по имени: `Справочники.<Имя>.<ИмяПредопределенного>`.

## Описания доработок — рекомендуемый состав

Собственный иерархический справочник **в том CFE, чьи доработки документируете**. Префикс расширения. Код длины 0, наименование 150.

Реквизиты:

- `КраткоеОписание` — `String(500) | multiline`
- `ПодробноеОписание` — `String(0) | multiline` (неограниченная)
- `ОбъектМетаданных` — `String(250)`
- `ВерсияПоявления` — `String(15)`
- `Актуально` — `Boolean` (не удалять предопределённый, а скрывать)

Макет объекта `ДанныеЗаполнения` — JSON-массив объектов (не CSV: точка с запятой в тексте ломает колонки). Модуль менеджера: экспорт `ОбновитьОписанияИзМакета`. Команда на форме списка.

Имена предопределённых — стабильный PascalCase, не переименовывать после появления в рабочих ИБ. Группы — по подсистеме/объекту.

## Как делать (скиллы)

XML руками не править.

1. `meta-compile` — справочник (иерархия, `predefinedDataUpdate: Auto`).
2. `meta-edit add-predefined` — элементы и группы. **Не** пересобирать объект `meta-compile` поверх существующего: сменятся UUID.
3. `template-add` — макет заполнения; тексты — в макете.
4. `form-add` / `form-compile` — список и элемент.
5. `role-compile` — просмотр (для настроек — ещё изменение).
6. `subsystem-edit` — показать в интерфейсе.
7. Фреш: заимствовать `ExchangePlan.МиграцияПриложений`, включить справочник, авторегистрация запрещена, признак изменения при подключении.
8. `1c-versioning` — поднять версию CFE.
9. `meta-validate` + `cfe-validate` + `validate_syntax-check` (MCP vrunner) + загрузка расширения.

Детали макета, обработчика и JSON-заготовки: [reference.md](reference.md).

## Жёсткие запреты

- Не пересобирать живой справочник через `meta-compile` — сломаются id предопределённых в ИБ.
- Не писать описания только в предприятии — на другой базе тексты пустые.
- Не менять `Name` предопределённого после поставки.
- Не править `Predefined.xml` руками.
- Не класть секреты и строки подключения в макет/элементы.
