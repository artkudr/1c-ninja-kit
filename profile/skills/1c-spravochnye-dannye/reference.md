# Справочные данные — детали

## Заготовка meta-compile (описания доработок)

Имя и префикс подставить из целевого CFE. Не компилировать поверх уже существующего объекта.

```json
{
  "type": "Catalog",
  "name": "ПрефиксОписанияДоработок",
  "synonym": "Описания доработок",
  "hierarchical": true,
  "codeLength": 0,
  "descriptionLength": 150,
  "autonumbering": false,
  "predefinedDataUpdate": "Auto",
  "quickChoice": false,
  "attributes": [
    { "name": "КраткоеОписание", "type": "String(500)", "multiLine": true },
    { "name": "ПодробноеОписание", "type": "String(0)", "multiLine": true, "extendedEdit": true },
    "ОбъектМетаданных: String(250)",
    "ВерсияПоявления: String(15)",
    "Актуально: Boolean"
  ],
  "predefined": [
    {
      "name": "ЗаказыКлиентов",
      "isFolder": true,
      "description": "Заказы клиентов",
      "childItems": [
        "ЗаказКлиента_АвтозаполнениеПодразделения [Автозаполнение подразделения заказа клиента]"
      ]
    }
  ]
}
```

Новые элементы в уже созданный справочник — только `meta-edit add-predefined`.

## Заполнение из макета

Ключ поиска — стандартный реквизит `ИмяПредопределенныхДанных`, не наименование.

Макет `ДанныеЗаполнения` — **текстовый JSON**, не CSV. Точка с запятой и кавычки в подробном тексте иначе сдвигают колонки.

```json
[
  {
    "ИмяПредопределенныхДанных": "ЗаказКлиента_Пример",
    "КраткоеОписание": "Кратко",
    "ПодробноеОписание": "Текст может содержать ; и кавычки «ёлочки».",
    "ОбъектМетаданных": "Документ.ЗаказКлиента",
    "ВерсияПоявления": "0.3.2.0",
    "Актуально": true
  }
]
```

Алгоритм менеджера:

1. Получить макет `ДанныеЗаполнения`, разобрать `ОбщегоНазначения.JSONВЗначение(Текст, Неопределено, Ложь)` — массив структур.
2. Для каждого элемента с непустым `ИмяПредопределенныхДанных` найти ссылку запросом к таблице справочника по полю `ИмяПредопределенныхДанных` (`НайтиПоРеквизиту` по стандартному имени нельзя).
3. Если ссылка пустая — пропустить (элемент ещё не создан платформой) или сообщить пользователю.
4. Получить объект, заполнить реквизиты из полей JSON, записать. `Актуально` — булево JSON, не строка `Истина`.

Широким `Попытка...Исключение` запись всего справочника не оборачивать. Не сравнивать булево с `Истина`/`Ложь`.

Команду обновления повесить на форму списка. Автозапуск при каждом старте сеанса не делать.

## Паттерн настроек (ecoladev)

Смотреть исходники:

- `ЭколаРеквизитыИНастройки_НастройкиАвтоматизации` — иерархия, `Значение` составной, `МножественноеЗначение`, ТЧ `Значения`, менеджер `Настройки(Элемент)`.
- Обращение: `Справочники.ЭколаРеквизитыИНастройки_НастройкиАвтоматизации.РозничныеАдминистраторы`.

Для **описаний** этот составной `Значение` не копировать.

## Платформа

- 8.3.20: предопределённые в **собственных** справочниках расширения.
- 8.3.21: также свои предопределённые у **заимствованных** справочников / ПВХ / планов счетов.
- В ecoladev у CFE `ConfigurationExtensionCompatibilityMode` = `Version8_3_27`.

Заимствованный предопределённый (`ExtensionState = AdoptedCheck`) — привязка к типовому элементу, не место для документации.

## Фреш

Новый справочник = объект данных. Обязательны план обмена `МиграцияПриложений`, без авторегистрации, признак «изменять значение при подключении расширения». Чеклист: скилл `1c-fresh-cfe-audit`.
