# Гайд в PDF

Markdown-гайд → PDF без pandoc и Word: печать Chromium через Playwright (он уже стоит у скилла `skill-web-test`), в запасе — Edge/Chrome в headless-режиме. Под это заточены гайды Барда `Задачи/<номер>/гайд.md`, но подойдёт любой Markdown.

## Запуск

```powershell
node "{{KIT_ROOT}}\profile\skills\skill-guide-pdf\scripts\build-guide-pdf.mjs" "Задачи/003 - 2026-11-17/гайд.md"
```

Путь — каталог скилла в репозитории кита (`active skills` ссылаются на него из `opencode.jsonc`); корень кита берётся из `$env:NINJA_KIT_ROOT` (переменную ставит `kit.ps1 apply`). Команда должна остаться одной строкой и начинаться с `node`.

PDF ложится рядом с исходником, имя то же с расширением `.pdf`.

| Ключ | Что делает |
|------|------------|
| `--out <файл.pdf>` | другой путь вывода |
| `--title`, `--subtitle`, `--date` | перекрывают блок метаданных и заголовок |
| `--keep-html` | оставить рядом `.html` — смотреть вёрстку в браузере |

Роль Барда запускает ровно эту команду: других команд у неё нет. Команда должна начинаться с `node` и содержать `build-guide-pdf.mjs` — иначе роль получит отказ в shell.

## Что понимает на входе

Заголовки `#`…`####`, абзацы, списки (в том числе вложенные), таблицы GFM, блоки кода, цитаты `>` (выводятся плашкой — так пишутся предупреждения), картинки `![подпись](путь)`, ссылки, `**жирный**`, `*курсив*`, `` `код` ``.

- Первый `#` становится заголовком обложки и из тела убирается.
- Раздел «Входные данные» (служебная шапка) в PDF не попадает.
- Картинка ищется относительно файла `.md`, потом относительно текущего каталога; в PDF она уходит base64, поэтому готовый файл не зависит от путей и переживает пересылку.
- Необязательный блок метаданных в начале файла:

  ```
  ---
  title: Дата начала действия у ставки НДС
  subtitle: Инструкция для пользователя
  date: 01.11.2026
  ---
  ```

## Вёрстка

A4, поля 16/16/20/16 мм, шрифт Segoe UI, колонтитул «Стр. N из M». Скриншоты не выше 115 мм, чтобы снимок с подписью не отрывался от шага; таблицы и картинки не разрываются между страницами, заголовки не остаются в конце страницы без текста.

Playwright ищется по порядку: пакет рядом со скриптом (`scripts/node_modules`), затем у соседнего скилла `skill-web-test` (`../skill-web-test/scripts/node_modules`), затем глобальный npm (`npm root -g`). Пути считаются от расположения самого скрипта, поэтому сборка не зависит от `~/.config` и текущего каталога. Свой Playwright можно указать путём к пакету или его `index.mjs` в переменной `GUIDE_PDF_PLAYWRIGHT`.

Если Playwright не нашёлся, берётся первый доступный браузер — Chromium из `%LOCALAPPDATA%\ms-playwright`, Edge или Chrome — и печатает `--headless=new --print-to-pdf`. В этом режиме номеров страниц нет: это аварийный путь, а не норма.

## Коды возврата

`1` — неверные аргументы, `2` — нет входного файла или в нём нечего печатать, `3` — рендер не запустился или PDF получился битым. Текст ошибки начинается со слова: `аргумент:`, `вход:` или `рендер:`.

## Правка инструмента

Стили — константа `CSS` в начале `scripts/build-guide-pdf.mjs`. Страницы и колонтитул — `renderWithPlaywright`. Разбор Markdown — `parseBlocks`/`parseList`/`parseTable`: это не полный CommonMark, а подмножество под гайды.

После правки разметки — прогон на живом артефакте и просмотр всех страниц: пустые хвосты страниц и разрыв внутри скриншота видны только глазами. PDF в PNG раскладывается так (нужен `pymupdf`):

```powershell
python -c "import pymupdf,sys; d=pymupdf.open(sys.argv[1]); [d[i].get_pixmap(dpi=110).save(f'p{i+1}.png') for i in range(d.page_count)]" guide.pdf
```

## Ограничения

- Один файл — один гайд; оглавления и перекрёстных ссылок с номерами страниц нет.
- Таблицы без объединённых ячеек; картинки — PNG/JPEG/GIF/WebP/SVG.
- Длинная строка в `код` не переносится.
- Контракт качества самого гайда (разделы, стиль, скриншоты) — в промпте роли Барда, а не здесь: скилл только собирает файл.
