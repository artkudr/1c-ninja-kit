# Ручные шаги для 1С:Фреш

Агент **не может** выполнить эти действия сам. В конце аудита/подготовки выведи блок **«НУЖНА РУЧНАЯ НАСТРОЙКА»** и перечисли только релевантные пункты (CFE / EPF / оба). Копируй формулировки близко к тексту ниже.

---

## Общие (CFE и EPF/ERF)

### 1. Стенд как в сервисе
- Развернуть сервер 1С версии, максимально близкой (для EPF — той же) к используемой в сервисе.
- Клиент-серверная ИБ нужной конфигурации и **той же версии**, что в сервисе.
- Веб-публикация ИБ (если средство не «только тонкий клиент»).

### 2. Тестовые пользователи
- Для каждого целевого профиля создать пользователя с тем же набором ролей, **без** роли `АдминистраторСистемы`.
- Прогнать весь функционал под этими пользователями в тонком и (если нужно) веб-клиенте.

### 3. Согласие на передачу данных наружу
- Если данные уходят за пределы сервиса — убедиться, что в сценарии есть явное подтверждение пользователя (и/или заявленные разрешения при установке).

### 4. Аудит и публикация
- Загрузка в сервис и отправка на аудит — через личный кабинет / обслуживающую организацию.
- При отказе — исправить замечания в карточке задачи и отправить повторно.
- Опционально: плагин EDT для предварительного аудита — https://www.1cfresh.com/articles/so_validation_plugin

## Только расширения (CFE)

### 5. Выгрузка и карточка
- Выгрузить расширение в `.cfe`.
- Подготовить описание, логотип **64×64**, скриншоты для карточки в сервисе.
- См. https://www.1cfresh.com/articles/so_confext_load

### 6. Разрешения при загрузке версии
Если используются операции вне безопасного режима, **при загрузке версии расширения в сервис** вручную указать разрешения, например:
- каталог временных файлов (чтение/запись);
- интернет-ресурсы (конкретные адреса);
- привилегированный режим.

Разрешения на внешние компоненты из состава конфигурации запрашивать не нужно — выдаются автоматически.

**Запрещено даже с разрешениями (на сервере):** произвольная файловая система (кроме temp), COM, чужие внешние компоненты, приложения ОС, криптография на сервере.

### 7. Конфигурации с изменением структуры данных
- Убедиться, что целевые конфигурации в сервисе поддерживают расширения, изменяющие данные.
- После автопроверки агента — визуально в конфигураторе проверить состав `МиграцияПриложений` (авторегистрация выкл., признак изменения при подключении).

## Только доп. отчёты и обработки (EPF/ERF)

### 8. Помощник комплекта поставки
1. Войти в личный кабинет сервиса → **Адаптация** → вкладка доп. отчётов/обработок → **Создать**.
2. Скачать `ПодготовкаДополнительныхОтчетовИОбработокКПубликацииВМоделиСервиса.epf`.
3. В локальной ИБ (администратор) открыть помощник через **Файл — Открыть** (не путать с отладкой самой обработки).
4. Указать источник (файл или элемент справочника), проверить реквизиты и **номер версии**.
5. Указать размещение команд (разделы / объекты назначения; для нескольких конфигураций — только общие объекты).
6. Сохранить **zip-комплект** (epf/erf + xml-манифест) на диск.

Документация: https://www.1cfresh.com/articles/so_addprocess_prep

### 9. Отладка «как в сервисе»
- Подключать и запускать обработку **через интерфейс БСП** «Дополнительные отчёты и обработки», а не через **Файл — Открыть**.
- Не тестировать только под полными правами.

### 10. Разрешения в коде vs установка
- Разрешения на небезопасные операции должны быть в `СведенияОВнешнейОбработке` (это проверяет агент).
- Пользователь при установке в приложении должен увидеть запрашиваемые ресурсы; при необходимости подтвердить доступ.
